# Synthetic EDA Tool Log Dataset Specification

> **NOTICE: SYNTHETIC DATA GENERATION**
> Synthetic data generated for demonstration. Not real EDA tool logs.
> All datasets, tool outputs, message logs, and metrics in this project are synthetically generated
> to model realistic semiconductor physical design and verification workflows without proprietary IP.
> Never claim these models work on real production EDA logs without retraining and verification on genuine telemetry.

---

## 1. Problem Setting & Motivation

Semiconductor design teams run tens of thousands of compute-intensive Electronic Design Automation (EDA) jobs across stages:
- **Synthesis** (RTL to gate-level netlist conversion)
- **Place and Route (P&R)** (physical floorplanning, placement, clock tree synthesis, routing)
- **Verification** (logic simulation, static timing analysis, formal verification)

Engineers waste considerable time manually reading massive (often multi-megabyte) unstructured text logs to diagnose why a job aborted, whether memory usage or execution duration is anomalous, and how long similar upcoming designs will run.

FlowInsight generates realistic, structurally authentic logs with controlled complexity, noisy indicators, edge-case artifacts, and injected anomalies to test analytics and ML modeling capabilities.

---

## 2. Dataset Schema

Every synthetic job generated by FlowInsight produces:
1. A structured manifest record (`data/manifest.csv` and database table `jobs`)
2. A raw text log file in `data/logs/{job_id}.log`
3. Ground-truth anomaly labels (`data/anomalies.csv` or columns in manifest)

### Manifest Fields

| Field | Type | Description |
|---|---|---|
| `job_id` | string | Unique identifier formatted as `JOB-SYNTH-{uuid}` or sequential `JOB-{stage_prefix}-{id:05d}` |
| `stage` | string | One of `synthesis`, `place_and_route`, `verification` |
| `design_name` | string | Representative chip block (e.g. `riscv_core`, `gpu_shader_slice`, `dram_ctrl`) |
| `design_size` | integer | Total standard cell/gate count, range $50{,}000$ to $2{,}500{,}000$ gates |
| `tool_version` | string | EDA tool release string (e.g., `v2023.03-SP1`, `v23.10-s095_1`) |
| `config_json` | string | JSON object containing run configurations (clock period, effort, layers, threads) |
| `start_time` | string | ISO-8601 UTC timestamp |
| `runtime_s` | float | Wallclock runtime in seconds |
| `peak_memory_mb` | float | Maximum resident set size (RSS) memory in megabytes |
| `warnings_count` | integer | Number of warning lines logged |
| `errors_count` | integer | Number of error lines logged |
| `status` | string | `completed` or `failed` |
| `failure_cause` | string | `none` (for completed) or one of 7 failure categories |
| `is_anomaly` | integer | Binary label: 1 if an injected anomaly was applied, 0 otherwise |
| `anomaly_type` | string | `none`, `runtime_spike`, `memory_growth`, or `warning_storm` |
| `is_truncated` | integer | Binary label: 1 if the log was abruptly truncated |

## 3. Failure Causes and Noisy Evidence Signatures

Failures occur in approximately 18% to 25% of jobs across stages. A failed job is assigned exactly one primary ground-truth root cause from the following taxonomy:

| Failure Cause | Applicable Stages | Characteristic Log Markers | Ambiguity & Noise Factors |
|---|---|---|---|
| `out_of_memory` | All | `[MEM-902] Fatal memory allocation failure`, `cgroup limit exceeded`, `Linux oom-killer invoked` | May be preceded by library loading warnings or slow garbage collection lines. |
| `timeout` | All | `[TIME-501] CPU execution limit exceeded`, `Process killed by watchdog timer`, `Elapsed wallclock time limit reached` | Often preceded by heavy DRC or timing loops, making cause look like congestion or timing violations. |
| `missing_library` | All | `[LIB-204] Cannot resolve target technology cell 'INV_X4_LVT'`, `Library search path does not contain .lef`, `Technology file not loaded` | Can appear early in compilation or late during cell replacement. |
| `constraint_violation` | All | `[TIM-302] Setup slack violation exceeds threshold: -1.42ns`, `[DRC-401] Max transition violation`, `Hold time violation` | Normal runs also contain minor non-fatal timing warnings. |
| `license_error` | All | `[LIC-101] FLEXlm error: Cannot checkout feature`, `License server unreachable at 27000@lic-server`, `License checkout timed out` | May occur at startup or mid-run during multi-threaded worker checkouts. |
| `syntax_error` | All | `[HDL-105] Syntax error in file 'rtl/alu_unit.v'`, `[SDC-201] Syntax error parsing constraint file`, `unexpected token` | Only fatal during elaboration/preprocessing, but warnings might refer to deprecated syntax. |
| `congestion` | `place_and_route` only | `[RTE-702] Global routing failed: Gcell congestion overflow exceeds 5.2%`, `[CONG-801] Congestion map hotspot exceeds routability threshold` | High pin density and timing violations often coincide, creating mixed signal features. |

### Ambiguity and Real-World Noise
To prevent models from relying on single trivial keyword lookups:
- Successful jobs occasionally contain benign warning messages with strings like `license check verified after 1 retry` or `minor slew transition warning`.
- Truncated logs may end before the explicit fatal message, requiring the model to infer cause from late-stage warning trajectories and memory ramp rates.
- Noisy logs inject background message IDs from harmless subsystems (`[INFO-012]`, `[CMD-001]`, `[ENV-100]`).

## 4. Runtime and Memory Generative Formulas

The synthetic generator uses non-linear parametric physical scaling models with calibrated stochastic noise:

### Parameters & Modifiers
- **Base Size Normalized**: $S = \frac{\text{design\_size}}{10^5}$
- **Effort Factor**:
  - `low`: $0.75$
  - `medium`: $1.00$
  - `high`: $1.35$
  - `extreme`: $1.85$
- **Thread Scaling**: $\eta_{\text{thread}} = (\text{thread\_count})^{-0.5}$ (Amdahl's law diminished returns)
- **Target Optimization Multiplier**:
  - `area`: $0.95$
  - `power`: $1.05$
  - `timing`: $1.20$
- **Routing Layer Factor** (P&R only): $1.0 + 0.05 \times (\text{layers} - 4)$
- **Random Multiplicative Noise**: $\epsilon \sim \text{Lognormal}(0, \sigma^2)$ where $\sigma = 0.12$

### Stage Runtime Models ($T$ in seconds)
1. **Synthesis**:
   $$T_{\text{synth}} = 120 \times S^{1.15} \times \text{effort\_mult} \times \text{target\_mult} \times (\text{threads})^{-0.55} \times \epsilon$$
2. **Place and Route**:
   $$T_{\text{pnr}} = 280 \times S^{1.35} \times \text{effort\_mult} \times \text{layer\_mult} \times (\text{threads})^{-0.45} \times \epsilon$$
3. **Verification**:
   $$T_{\text{verif}} = 90 \times S^{1.05} \times \text{effort\_mult} \times (\text{threads})^{-0.35} \times \epsilon$$

### Peak Memory Models ($M$ in Megabytes)
- **Base Memory Floor**: $800\text{ MB}$
- **Growth Law**:
  $$M = 800 + 450 \times S^{1.08} \times K_{\text{stage}} \times \left(1 + 0.04 \times \text{threads}\right) + \mathcal{N}(0, 75^2)$$
  where $K_{\text{stage}} = 1.0$ (synthesis), $1.65$ (P&R), $0.75$ (verification).

## 5. Injected Anomalies

Anomalies represent abnormal execution deviating substantially from the expected physical scaling model:

1. **`runtime_spike`** (Probability: ~3%):
   Execution time multiplies by a factor of $3.5\times$ to $6.0\times$ due to simulated optimizer convergence lock, pathological routing detours, or network filesystem latency.
2. **`memory_growth`** (Probability: ~3%):
   Peak memory balloons by $2.5\times$ to $4.2\times$ due to unconstrained flatten operations or memory leaks.
3. **`warning_storm`** (Probability: ~3%):
   Warning count multiplies to $200$ to $600+$ messages caused by cascading DRC errors or unconstrained clock domains.

---

## 6. Messy Real-World Artifacts

To prevent clean-data bias, the generator injects:
1. **Truncated Logs** (~4% of jobs): Simulates sudden host kernel crash, disk out-of-space, or kill signal. The file cuts off abruptly in the middle of a log line.
2. **Repeated Warning Floods**: Hundreds of identical warning lines repeated across iterations.
3. **Unknown/Custom Message Formats**: Tool wrappers print non-standard messages: `**DIAG-NOTICE**`, `Tcl Script Note:`, `DEBUG_CORE:`.
4. **Tool Version Syntax Variations**:
   - `v2023.*`: Uses standard bracket notation `[WARN:ID]`
   - `v2024.*`: Uses timestamp prefixes and severity prefixes `[2024-04-10T12:00:00] [WARN] [ID]`
   - `legacy / patch`: Uses asterisks `**WARNING: (MSG-102)`

---

## 7. Determinism and Reproducibility

- The generator is completely deterministic when initialized with a fixed seed (default `--seed 42`).
- Default dataset size is 5,000 jobs.
- All ground-truth labels are exported to `data/manifest.csv` and stored in SQLite `jobs` table.
